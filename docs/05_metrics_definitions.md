# Определения метрик NeoBank

**Правило:** у каждой метрики — **одно** определение. Если определение меняется — это новая метрика. Без этого метрики «плавают» и анализ врёт.

## 1. Acquisition (привлечение)

### 1.1. Registrations

- **Определение:** количество уникальных клиентов, зарегистрировавшихся за период.
- **Формула:** `COUNT(DISTINCT client_id) WHERE registered_at IN period`.
- **Граничные случаи:** дубликаты email/телефона — считаем уникальные `client_id`.
- **Где используется:** воронка, CAC, анализ каналов.

### 1.2. CAC (Customer Acquisition Cost)

- **Определение:** средняя стоимость привлечения одного клиента.
- **Формула:** `маркетинговые расходы / количество регистраций`.
- **Граничные случаи:** расходы — только маркетинг (не зарплаты).
- **Где используется:** LTV/CAC, анализ эффективности каналов.

### 1.3. Conversion to Registration

- **Определение:** доля установивших приложение, которые зарегистрировались.
- **Формула:** `registrations / installs`.
- **Где используется:** воронка acquisition.

## 2. Activation (активация)

### 2.1. Activation Rate

- **Определение:** доля зарегистрировавшихся, совершивших **первую транзакцию** в течение **14 дней** после регистрации.
- **Формула:** `COUNT(DISTINCT client_id с первой tx ≤ 14 дней) / COUNT(DISTINCT client_id зарегистрированных)`.
- **Граничные случаи:**
  - Fraud-клиенты исключаются (флаг `is_fraud = TRUE` на клиенте).
  - Если транзакция declined — не считается.
  - Окно — **14 календарных дней** от `registered_at`.
- **Где используется:** главная метрика онбординга, A/B.

### 2.2. Time to Activation

- **Определение:** медианное время от регистрации до первой транзакции.
- **Формула:** `MEDIAN(first_tx_at - registered_at)` для активированных.
- **Где используется:** качество онбординга.

### 2.3. Onboarding Completion Rate

- **Определение:** доля начавших онбординг, которые его завершили.
- **Формула:** `завершившие / начавшие`.
- **Где используется:** воронка онбординга.

## 3. Retention (удержание)

### 3.1. D7 Retention

- **Определение:** доля клиентов из когорты, вернувшихся (совершивших любую транзакцию) на **7-й день** после первой транзакции.
- **Формула:** `COUNT(DISTINCT client_id с tx на день 7) / COUNT(DISTINCT client_id в когорте)`.
- **Граничные случаи:** «день 7» — ровно 7-й день (не «7+»). Rolling retention считается отдельно.
- **Где используется:** здоровье продукта, когортный анализ.

### 3.2. D30 Retention

- **Определение:** аналогично D7, но на **30-й день**.
- **Где используется:** главная метрика здоровья.

### 3.3. M1, M3 Retention

- **Определение:** доля вернувшихся в течение **1-го / 3-го месяца** после первой транзакции (rolling).
- **Формула:** `COUNT(DISTINCT client_id с tx в месяце N) / COUNT(DISTINCT client_id в когорте)`.
- **Где используется:** долгосрочный retention.

### 3.4. Churn Rate

- **Определение:** доля клиентов, ушедших за период (нет транзакций 90+ дней).
- **Формула:** `COUNT(DISTINCT client_id с last_tx > 90 дней назад) / COUNT(DISTINCT client_id активных 90 дней назад)`.
- **Граничные случаи:** «ушедший» — 90 дней без транзакций. Порог можно менять (30/60/90).
- **Где используется:** прогноз оттока, ML.

### 3.5. Sticky Factor (DAU/MAU)

- **Определение:** отношение DAU к MAU — насколько часто возвращаются.
- **Формула:** `DAU / MAU`.
- **Где используется:** здоровье продукта (для банка — 20–40% норма).

## 4. Revenue (монетизация)

### 4.1. ARPU (Average Revenue Per User)

- **Определение:** средняя выручка на **всех** клиентов за период.
- **Формула:** `выручка / COUNT(DISTINCT client_id)`.
- **Граничные случаи:** знаменатель — все клиенты (включая неактивных).
- **Где используется:** монетизация, LTV.

### 4.2. ARPPU (Average Revenue Per Paying User)

- **Определение:** средняя выручка на **платящих** клиентов.
- **Формула:** `выручка / COUNT(DISTINCT client_id с выручкой > 0)`.
- **Где используется:** монетизация платящих.

### 4.3. LTV (Lifetime Value)

- **Определение:** суммарная выручка от клиента за всё время (или прогноз на горизонте).
- **Формула (историческая):** `SUM(выручка от клиента)`.
- **Формула (прогноз):** ML-модель (регрессия).
- **Граничные случаи:** для активных — прогноз; для ушедших — факт.
- **Где используется:** LTV/CAC, приоритизация.

### 4.4. AOV (Average Order Value)

- **Определение:** средний чек транзакции.
- **Формула:** `SUM(amount) / COUNT(tx_id)` для completed транзакций.
- **Где используется:** монетизация, сегментация.

### 4.5. Revenue

- **Определение:** выручка компании за период.
- **Формула (упрощённо):** `интерчейндж + проценты по кредитам + комиссии - процентные расходы по вкладам`.
- **Где используется:** P&L, ARPU.

## 5. Cross-sell (продажа дополнительных продуктов)

### 5.1. Cross-sell Rate

- **Определение:** доля клиентов с **2+ продуктами**.
- **Формула:** `COUNT(DISTINCT client_id с ≥2 активными продуктами) / COUNT(DISTINCT client_id активных)`.
- **Граничные случаи:** «активный продукт» — статус `active`. Закрытые не считаются.
- **Где используется:** главная метрика cross-sell.

### 5.2. Products per Client

- **Определение:** среднее число продуктов на клиента.
- **Формула:** `COUNT(client_product_id) / COUNT(DISTINCT client_id)`.
- **Где используется:** глубина отношений.

### 5.3. Cross-sell Matrix

- **Определение:** матрица «продукт A × продукт B» — сколько клиентов имеют оба.
- **Формула:** `COUNT(DISTINCT client_id с A AND B)`.
- **Где используется:** какие продукты продавать вместе.

## 6. Fraud (мошенничество)

### 6.1. Fraud Rate

- **Определение:** доля fraud-транзакций от всех.
- **Формула:** `COUNT(tx_id WHERE is_fraud = TRUE) / COUNT(tx_id)`.
- **Где используется:** риск-мониторинг.

### 6.2. Fraud Losses

- **Определение:** суммарный ущерб от fraud за период.
- **Формула:** `SUM(amount) WHERE is_fraud = TRUE AND confirmed = TRUE`.
- **Где используется:** P&L, ML-модель.

### 6.3. Precision (для fraud-модели)

- **Определение:** доля реальных fraud среди тех, кого модель назвала fraud.
- **Формула:** `TP / (TP + FP)`.
- **Где используется:** оценка модели (сколько ложных срабатываний).

### 6.4. Recall (для fraud-модели)

- **Определение:** доля пойманных fraud от всех fraud.
- **Формула:** `TP / (TP + FN)`.
- **Где используется:** оценка модели (сколько пропускаем).

### 6.5. PR-AUC (для fraud-модели)

- **Определение:** площадь под precision-recall curve.
- **Где используется:** главная метрика для imbalanced fraud-задач (не accuracy!).

## 7. A/B (эксперименты)

### 7.1. p-value

- **Определение:** вероятность увидеть такие или более экстремальные данные, если H0 верна (эффекта нет).
- **Порог:** 0.05 (5%).
- **Где используется:** значимость эффекта.

### 7.2. Confidence Interval (CI)

- **Определение:** диапазон, в котором с 95% вероятностью находится истинный эффект.
- **Где используется:** оценка эффекта (ширина = неопределённость).

### 7.3. MDE (Minimum Detectable Effect)

- **Определение:** минимальный эффект, который тест может обнаружить при данном sample size и мощности.
- **Где используется:** планирование A/B (до запуска).

### 7.4. SRM (Sample Ratio Mismatch)

- **Определение:** ситуация, когда группы в A/B неравны по размеру (хотя должны быть).
- **Проверка:** chi-square тест на равенство долей.
- **Где используется:** валидация A/B (до анализа).

## 8. Продуктовые метрики (сводно)

| Категория   | Метрика         | Формула (кратко)                      |
| ----------- | --------------- | ------------------------------------- |
| Acquisition | Registrations   | `COUNT(DISTINCT client_id)`           |
| Acquisition | CAC             | `маркетинг / регистрации`             |
| Activation  | Activation Rate | `активированные / зарегистрированные` |
| Retention   | D7/D30          | `вернувшиеся на день N / когорта`     |
| Retention   | Churn           | `ушедшие / активные 90 дней назад`    |
| Revenue     | ARPU            | `выручка / все клиенты`               |
| Revenue     | LTV             | `SUM(выручка клиента)` или ML         |
| Cross-sell  | Cross-sell Rate | `клиенты с 2+ продуктами / активные`  |
| Fraud       | Fraud Rate      | `fraud tx / все tx`                   |
| Fraud       | Precision       | `TP / (TP + FP)`                      |
| A/B         | p-value         | (статистика)                          |

## 9. Правила использования

1. **Одна метрика — одно определение.** Если нужно другое — новая метрика с суффиксом (`_v2`).
2. **Всегда указывать период.** «Retention D7 за январь» — ок. «Retention D7» — нет.
3. **Всегда указывать фильтры.** «Activation rate для paid-канала» — ок.
4. **Документировать граничные случаи.** Fraud-клиенты, declined-транзакции, TZ.
5. **Проверять гранулярность.** Метрика на клиенте ≠ метрика на транзакции.
